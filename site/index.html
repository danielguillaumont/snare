Legitimate work never touches a trap.

Prompt injection has no complete fix, and a hijacked agent acts with its own permissions, so normal logs see nothing odd. Snare plants decoy tools, honey credentials and canaries where agents work. When one is touched, you get an alert that names the trap, the session and what the agent read just before.

How it works

One trap per stage of an attack

The gateway wraps an agent's real MCP server and relays its traffic unchanged. Touches from one session form an incident, ranked by the deepest stage it reached. Two stages in one session make it Critical.

steered

Context canaries and tool integrity

A leaked system prompt or acted-on memory fires. So does a tool whose description changed after it was pinned.

recon

Decoy tools

Decoys inside the real server's tool list, named the way that server names things. Screened against benign tasks before they ship.

collection

Honey credentials and early warning

Planted keys, URLs and hosts. When one comes back in a tool result, the agent has read it: that's a warning.

exfiltration · use

Egress and use

A honey value in any real tool's arguments, or presented as a credential anywhere, alerts. Containment can block the call.

Alerts are OCSF 1.3 Detection Findings, sent to a signed webhook, Splunk, Elastic, Sentinel or Slack. Each touch carries fingerprints of the agent's last 8 inputs, so the alert names the file that steered it.

What we measured

Pre-registered, including the misses

Every rule was fixed before its run. Intervals are 95% Wilson. Models are Claude Haiku, Sonnet and Opus, in our own scripted environments and in AgentDojo. Total spend so far is about $34.

What holds up

  • False alarms stay near zero across every run, three models and an outside benchmark.
  • Every run that sent a real secret out through a tool was caught (17/17, post-hoc).
  • Most agents that slipped past the traps had read the honey file first. That read is now on the record.

What doesn't, yet

  • More decoys didn't catch more agents, and a long tool list tripled text-only declines.
  • 57 of the 106 M16 runs have only a warning, which doesn't page anyone.
  • Claude models rarely got hijacked in our lab, so detection of real hijacks needs real deployments.

Every number links to its denominator and raw data in FINDINGS.md.

Try it

Two commands, nothing leaves your machine

Static binaries for Linux, macOS and Windows are on the releases page, signed keylessly in CI.

# replay the hijack above through a real gateway, with a dashboard
snare demo -attack

# find your MCP client configs and plan which servers to wrap (dry run)
snare init
snare init -apply   # back up, wrap, verify each alert path, print coverage
